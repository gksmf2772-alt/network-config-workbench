# UI Rules

## 1. 기본 원칙

- 사용자가 요청하지 않은 UI 변경 금지.
- 기존 색상, 간격, 폰트, 버튼 스타일 임의 변경 금지.
- 기존 레이아웃 구조 임의 변경 금지.
- 기능 수정 중 디자인 개선을 끼워 넣지 말 것.
- UI 수정이 필요한 경우 변경 전후 또는 검증용 캡처를 남길 것.

## 2. 변경 가능 항목

사용자가 명시적으로 요청한 경우에만 다음을 변경한다.

- 색상
- 폰트
- 간격
- 레이아웃
- 메뉴 구조
- 아이콘
- 버튼 스타일
- 카드 스타일
- 모달 디자인
- 반응형 동작

## 3. UI 수정 시 필수 확인

- 데스크톱 화면 확인.
- 모바일 화면 확인이 가능한지 확인.
- 주요 버튼 클릭 확인.
- 입력창/드롭다운 동작 확인.
- 스크롤 동작 확인.
- 콘솔 에러 확인이 가능한지 확인.
- 네트워크 에러 확인이 가능한지 확인.
- 변경 전후 또는 검증용 캡처 저장.

## 4. 캡처 저장 위치

`docs/verification/screenshots/<YYYY-MM-DD>/<task-name>/`

## 5. 현재 작업 특이사항

- 리포트 상세 필드의 규칙 추가 UI는 기본 노출하지 않고 아이콘 클릭 시 팝오버로 표시한다.
- 팝오버는 절대 위치로 표시해 카드 높이와 주변 카드 그리드를 밀지 않게 한다.
- 팝오버 내부 드롭다운과 버튼은 텍스트가 잘리지 않도록 독립 폭과 높이를 유지한다.
- 리포트 상세 필드 카드 헤더는 `필드명 / 상태 / 규칙 아이콘` 3열 구조를 유지해 상태 라벨 위치가 흔들리지 않게 한다.
- 규칙이 적용된 리포트 상세 필드 카드는 초록 계열 배경/테두리로 일반 카드와 구분한다.
- 적용된 규칙을 프로파일 예외 id로 추적할 수 있으면 `+` 대신 `-` 버튼을 표시해 해제할 수 있게 한다.
- 적용 상태는 있지만 해제할 수 있는 단일 예외 id가 없으면 `-` 대신 체크 마커만 표시한다.
- `ingress-filter`, `egress-filter`, `ingress-qos`, `egress-qos` 같은 중요 정책 필드도 규칙 적용 후 같은 적용 카드/`-` 버튼 규칙을 따른다.
- 재비교 전 stale 리포트 row라도 현재 프로파일에 같은 필드 예외가 저장되어 있으면 `+` 대신 `-`를 표시한다.
- 관계 그래프 툴바의 `라벨` 토글은 줄바꿈 없이 한 줄로 표시되게 최소 폭과 `white-space: nowrap`을 유지한다.
- 리포트 검토 테이블은 항목이 많아질 때 `.report-review-table-wrap` 내부에서 스크롤되게 유지한다.
